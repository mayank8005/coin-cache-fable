🔒 How your data stays yours

Every layer — from the database to the browser cookie — is locked down by design.

🔑 Passwords

Hashed with bcrypt at cost 12. Login is timing-safe — a full hash comparison runs even for unknown email addresses, so response time reveals nothing.

🍪 Sessions

Random 256-bit tokens stored only as SHA-256 hashes in the database. The browser cookie is httpOnly + SameSite=Lax + Secure (when on HTTPS). 60-day sliding expiry. Changing your password revokes all other sessions immediately.

🚦 Brute-force protection

Login rate limiting: max 10 attempts per email and 20 per IP per 15 minutes, tracked in the database so a container restart does not reset the counter. Verified: the 11th attempt is blocked.

🚪 No public signup

Only the admin can add users. The initial setup wizard locks itself permanently after the first account is created, so the door cannot be reopened.

🌐 Transport & HTTPS

Caddy reverse proxy handles automatic Let's Encrypt certificate issuance and renewal. HSTS is enabled so browsers always use HTTPS after the first visit.

🛡️ Security headers

Strict Content-Security-Policy, X-Frame-Options: DENY, X-Content-Type-Options: nosniff, Referrer-Policy, and Permissions-Policy applied on every response.

✅ Input & query safety

Every mutation validated with Zod on the server. All database queries go through Prisma's parameterized interface — no raw SQL interpolation, no injection surface. CSRF is covered by Next.js server-action origin checks combined with SameSite cookies.

🔌 Network isolation

PostgreSQL and the app container publish no ports to the host. Only Caddy (ports 80 and 443) is reachable from the internet. The database password lives in .env on your server and never leaves it.

📦 Container hardening

The app runs as a non-root user inside a minimal Alpine image, reducing the blast radius of any hypothetical vulnerability to near zero.

🙈 Zero third parties

No analytics, no trackers, no external fonts or CDNs — the app makes no outbound requests at all. Nothing can leak; there is no one to leak to.

🧱 Data isolation

Every query is scoped to the signed-in user server-side; ownership of every record, account and category is verified on each mutation. Verified with two concurrent users.

💾 Automatic backups

scripts/backup.sh runs a pg_dump nightly via cron and keeps the last 30 dumps, so a one-line crontab entry is all you need to never lose data.

⚙️ Architecture & technical decisions

Boring choices, on purpose. Every decision optimises for long-term maintainability over novelty.

Decision Choice Why
Framework Next.js 15 (App Router) + React 19 One codebase serves both frontend and backend via server actions — fewer moving parts, fewer services to operate.
Monorepo npm workspaces apps/web (the app) + packages/shared (CSV parser + defaults, unit-tested). Clean separation without the overhead of a full monorepo tool.
Database PostgreSQL 16 + Prisma 6 ORM Proven, reliable, and self-hostable. Schema migrations apply automatically on container boot — zero manual steps on upgrade.
Money storage BigInt minor units (paise) No floating-point errors, ever. Supports very large amounts without precision loss.
Ledger model Independent per-user spaces Each family member gets a fully private ledger — like giving each person their own app behind one login page; even the admin cannot see others' data.
Styling & charts Tailwind CSS 4 + hand-drawn SVG donut No chart library dependency. The donut is a small amount of SVG math — fast, fully controlled, zero bloat.
Auth Email + password, DB-backed sessions Intentionally boring. No OAuth dependency, works fully offline from the internet giants, impossible to break via a third-party auth outage.
Deployment Multi-stage Dockerfile + docker compose Node 22 Alpine base, Next.js standalone output. Runs db + web + caddy in one compose file. Resource footprint is tiny — well under 1 GB RAM on an 8 GB VPS.
Timezone Configurable (default Asia/Kolkata) Day/week/month boundaries match your life, not wherever the server happens to sit. Change it once in Settings.
