🚀 Run it locally, deploy it for real

Two paths: a quick local spin with Docker Desktop, or a proper production deployment on your Hostinger VPS with automatic HTTPS.

On this page A. Run locally B. Deploy on a Hostinger VPS C. First-run setup D. Backups & disaster recovery Troubleshooting Security reminders

🖥️ A. Run locally

For trying CoinCache out, or for development.

📋 Prerequisite

Docker Desktop. That's the whole list.

⚡ Quick way (full stack in Docker)

cp .env.example .env      # defaults are fine locally; DOMAIN empty = plain HTTP on port 80
docker compose up -d --build
open http://localhost

🔁 Dev mode (hot reload)

Install dependencies, keep the compose database running (or any Postgres), then start the dev server:

npm install
DATABASE_URL=postgresql://coincache:<DB_PASSWORD>@localhost:5432/coincache npm run dev
⚠️
The compose file intentionally does not publish the Postgres port. For dev, either run your own Postgres or temporarily add ports: ["5432:5432"] to the db service.

🧪 Unit tests

npm test

🌐 B. Deploy on a Hostinger VPS

An 8 GB VPS is plenty — idle usage is well under 1 GB RAM.

Point DNS first. Create an A record for e.g. money.yourdomain.com → your VPS IP. Do this before deploying so Let's Encrypt can validate the domain immediately.

SSH in.

ssh root@your-vps-ip

Install Docker if it's missing.

curl -fsSL https://get.docker.com | sh

Get the code onto the VPS.

git clone <your repo> coincache
# — or from your machine —
scp -r ./coin-cache-fable root@vps:/opt/coincache

Configure the environment.

cd /opt/coincache
cp .env.example .env

Then edit .env:

  • DB_PASSWORD → the output of openssl rand -hex 24 (hex only — characters like / + = @ break the database URL)
  • DOMAIN → money.yourdomain.com
  • TZ → Asia/Kolkata

Open the firewall (if ufw is active).

ufw allow 80/tcp && ufw allow 443/tcp

Build and start.

docker compose up -d --build

The first build takes a few minutes. Migrations run automatically, and Caddy fetches the HTTPS certificate on the first request.

Open https://your-domain — continue in section C.

Backups. Nightly pg_dump, keeps the last 30 in ./backups.

chmod +x scripts/backup.sh
crontab -e
# add this line:
0 2 * * * /opt/coincache/scripts/backup.sh

Occasionally copy a dump off the VPS for extra safety.

Updating. Pull or copy the new code, then rebuild — your data lives in the db_data Docker volume and survives rebuilds.

docker compose up -d --build

🏁 C. First-run setup — from empty app to daily use

The containers are up. Here's how to go from a blank app to your family tracking every rupee.

C1Create the admin account

The very first visit redirects to a one-time /setup page. It only exists while the app has zero users; afterwards it permanently redirects to the login page, so nobody else can ever grab it.

  • Enter your name, email (this is your sign-in), and a password — minimum 8 characters; use a unique one from a password manager.
  • Submitting creates the ADMIN account, seeds your space with the default categories and a Cash account, and signs you in.
  • The admin role is only for managing logins: adding family members and resetting their passwords. Each member — including the admin — has their own completely private space.

C2Set preferences

Settings → Preferences: pick your currency (any 3-letter ISO code; INR default, shown with Indian digit grouping) and timezone (Asia/Kolkata default) — the timezone controls what "today" and day/week/month boundaries mean.

C3Create your accounts

Settings → Accounts: Cash already exists; add Bank, Credit card, UPI etc., each with an emoji and an initial balance so the header balance starts correct.

C4Import your old data

  • In your old expense app, look for a Data backup / Export to CSV option. Transfer the file to the phone or computer you're using.
  • In CoinCache: Settings → Data → choose the file → Import CSV.
  • Date order, delimiter and decimal style are auto-detected (with a manual Day/Month override); Skip duplicates makes re-imports safe; unknown categories and accounts are created automatically.

C5Add family members

Settings → Family & security → Add family member: name, email, and a temporary password (min 8 chars). Share it with them; they sign in and change it via Change my password — which signs out their other devices. There is no public registration page.

The new member gets their own seeded private space (default categories + a Cash account) the moment they're created — and the admin cannot see their records.

C6Install on your phones

  • Android / Chrome: menu ⋮ → Add to Home screen / Install app.
  • iPhone / Safari: Share → Add to Home Screen.

Opens fullscreen like a native app.

C7Forgotten passwords (recovery)

A family member forgot theirs: the admin opens Settings → Family & security, taps Reset password next to their name, and sets a new one — their other devices are signed out. Verified working.

The ADMIN forgot theirs: there is no email-reset by design (no outbound email = nothing to leak). Instead, run the built-in emergency reset tool on the VPS — it ships inside the app container, works for any user, keeps all data, and signs that user out everywhere: 

docker compose exec web node /opt/tools/reset-password.js you@example.com 'new-password'
⛔
Never delete rows from the "User" table. Since every user owns their space, deleting a user permanently deletes all of their records, accounts and categories (cascade).

C8Post-setup checklist

  • Padlock / HTTPS visible in the browser (Caddy + Let's Encrypt working).
  • Backup cron installed (section B) — and test a restore once, following the verified procedure in section D.
  • .env never committed / copied anywhere public.
  • Keep the VPS patched: apt update && apt upgrade periodically, or enable unattended-upgrades.
  • Optional hardening: SSH key login only (disable password auth in sshd_config).

💾 D. Backups & disaster recovery

Every command in this section was executed and verified today — this is the tested path back from any disaster.

D1The golden rules

✅ SAFE

Data always survives these:

  • git pull
  • docker compose up -d --build
  • docker compose restart / stop / start
  • docker compose down (WITHOUT -v)
  • VPS reboots

⛔ DESTRUCTIVE

These delete the database:

  • docker compose down -v
  • docker volume rm / docker volume prune

Never use -v once you have real data.

Data lives in the db_data Docker volume, not in containers.

D2Backups

Automatic nightly:

crontab -e
# add this line (keeps the last 30 in ./backups):
0 2 * * * /path/to/coincache/scripts/backup.sh

Manual, anytime:

./scripts/backup.sh

Dumps are created with pg_dump --clean --if-exists, so a single file restores over an existing database OR into a brand-new empty one.

Copy a backup off the VPS occasionally — a backup on the same disk as the database is only half a backup. From your laptop: 

scp root@YOUR-VPS-IP:/path/to/coincache/backups/coincache-DATE.sql.gz .

D3Restore a backup (app still running)

For example after a bad import or accidental deletions:

cd /path/to/coincache
docker compose stop web
gunzip -c backups/coincache-DATE.sql.gz | docker compose exec -T db psql -q -U coincache -d coincache
docker compose start web
💡
This restores everything as of the backup moment — records, users, even passwords. Verified: zero errors, deleted records came back.

D4Total loss (volume deleted, disk died, or moving to a new VPS)

Get three things onto the machine: the repo, your .env, and a backup file. Then:

docker compose up -d db          # start ONLY the database, fresh and empty
# wait ~10 seconds for it to become healthy
gunzip -c backups/coincache-DATE.sql.gz | docker compose exec -T db psql -q -U coincache -d coincache
docker compose up -d             # start the rest; migrations recognise the restored state automatically

Verified end-to-end today: fresh volume, zero restore errors, all records recovered, app healthy.

D5After any restore

Open the site and spot-check your records; you may need to sign in again. Test the whole procedure once now, while the stakes are low — a backup you've never restored is a hope, not a plan.

🔧 Troubleshooting

  • docker compose ps — check the status of all three containers.
  • docker compose logs web / caddy / db — read the logs of a specific service.
  • Seeing "database not ready, retrying" for a few seconds at first boot is normal — the app waits for Postgres.
  • HTTP 502 with "Authentication failed against database server" in the web logs: DB_PASSWORD in .env was changed after the database volume was first created — Postgres only reads it on first init. Either reset the data (docker compose down -v && docker compose up -d — deletes all records) or keep the data and sync the password in place:
    echo "ALTER USER coincache WITH PASSWORD :'pw';" | docker compose exec -T db psql -U coincache -d coincache -v pw="$(grep '^DB_PASSWORD=' .env | cut -d= -f2-)"
    then docker compose restart web.
  • Browser can't connect? Check the DNS A record and the firewall (ports 80 and 443).
  • HTTPS requires DOMAIN to be set and ports 80 + 443 reachable from the internet — Let's Encrypt validates over them.

🔒 Security reminders

  • Never expose port 5432 (Postgres) to the internet.
  • Keep .env out of git — it's already gitignored; leave it that way.
  • Always use a real DOMAIN (HTTPS) in production: Secure cookies and HSTS depend on it. An empty DOMAIN (plain HTTP on port 80) is only for a first local smoke test.
